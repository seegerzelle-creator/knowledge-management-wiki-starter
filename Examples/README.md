# 先看一条问题怎样变成问题卡

这里全部是虚构教学材料，不来自真实个人笔记或外部文章。Seed 可以理解为“可继续追踪的问题卡”。

你可以对 Codex 说：

> 请解释下面的 Capture 到 Seed 示例，只读，不复制到我的 Raw/Wiki，也不创建个人文件。

## Capture → Seed：确认发生在哪里

示例从 [一条原始捕捉](<Raw/Captures/示例 - 如何让阅读真正转化为行动.md>) 开始，最后形成 [问题卡](<Wiki/seeds/示例种子 - 阅读与行动之间的断层.md>)。下面每句用户回复都只是虚构演示。

1. **保存原文。** Agent 原样保存并验证，问：“你当时针对哪种阅读，想完成什么事情？”此时不生成理解或知识关联。
2. **补充并确认背景。** 用户答：“我想把工作方法文章用于每周会议，不是文学阅读。”Agent 复述背景请其确认。用户答：“背景准确，请给理解预览。”
3. **确认理解与追加范围。** Agent 预览：“你关心方法阅读怎样进入实际工作；目前不能判断没行动的原因。”用户答：“理解准确，确认追加这份理解对齐版，并给我看 Seed 草案。”此时只获准追加理解和预览草案，还没有建 Seed。
4. **搜索与具体草案。** Agent 追加已批准的理解版，再搜索正式 Wiki 中的近义 Seed；有同问题页则优先提出更新方案。草案列明实际目标、最短原句、Raw 来源、待追踪问题、下一步，以及需修改的导航/日志。搜索若改变已批准方案，说明变化部分。
5. **批准后写入。** 用户看过草案后说：“按这份草案写入，并更新预览中列出的导航和日志。”Agent 才按范围创建或更新问题卡、回读验证，报告实际修改。问题尚未成熟，不自动升级为概念或综合判断。

保存、背景确认、理解追加和 Wiki 写入分别判断授权；已经清楚且仍有效的授权不重复询问。你始终可以纠正理解、只留 Raw，或结束。

示例 Raw 保持未整理状态，上述背景只帮助说明示例问题卡如何形成，不代表真实对话已经发生。示例中的确认不能用于批准你自己的操作。
